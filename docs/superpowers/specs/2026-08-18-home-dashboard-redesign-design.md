# 首頁儀表板改版設計

日期：2026-08-18
狀態：待實作
範圍：輸入籌碼與盲注後進入的主畫面，以及隨之而來的導覽結構調整

## 背景

現在的主畫面（`ResultView`）是一條單線流程的終點：籌碼輸入 → 盲注輸入 → 結果頁。所有次要功能靠 sheet 疊上去，底部固定列擠著三顆按鈕（重置／籌碼變化／編輯盲注），其中重置一場牌局頂多按一次卻長期佔位又容易誤觸。

實際使用情境是錦標賽／SNG 的實體牌桌：單手操作、光線偏暗、需要幾秒內判讀。使用者八成以上打開這頁是為了**輸入這手贏／輸了多少**，BB 深度是輸入完的回饋。

## 目標

1. 把「記錄這手輸贏」變成畫面上最順的一條路徑
2. 現有功能一個都不藏，改用標準導覽讓它們各就各位
3. 補上錦標賽真正需要、但目前沒有的數字：**升盲後還剩幾 BB**

## 非目標

- 不做視覺規範改版（色彩、字級、間距、動效沿用現有 `Theme`，實作出來再迭代）
- 不做現金桌的買入／回補統計
- 不改行動線記錄、計時器設定、籌碼／盲注輸入頁的內部內容

## 導覽結構

從單線流程改成 `TabView` 四分頁。首次啟動仍走 onboarding → 籌碼 → 盲注，走完才進 Tab 介面；之後冷啟動直接進儀表板。

| 分頁 | 內容 | 來源 |
| --- | --- | --- |
| 儀表板 | 狀態卡、籌碼變化卡、升盲倒數卡 | 改造 `ResultView` |
| 行動線 | 記錄列表（編輯器仍以 sheet 全螢幕開啟） | `HandActionLineSheet` 升格 |
| 紀錄 | 籌碼變化歷史，日後長成本場統計 | `ChipChangeHistorySheet` 升格 |
| 設定 | 計時器設定入口、重置、關於 | `TimerConfigSheet` 入口 ＋ 從底部搬來的重置 |

決定與理由：

- **分頁列用 iOS 標準樣式，四個分頁都有文字標籤**。先前的無標籤圖示列讀不出來。
- **編輯籌碼總額與編輯盲注不佔分頁**，仍從儀表板卡片點進去，沿用現有畫面。
- **分頁選擇不持久化**，冷啟動一律回儀表板——在牌桌上打開 App 就是要看深度。
- **計時器設定維持 sheet**，設定分頁只放入口。它是多步驟長流程，塞進分頁反而難用。
- **重置移進設定分頁**，離開誤觸範圍。

## 儀表板

三張卡。一般字級下一頁到底不需捲動；放大字級時允許捲動。

### 狀態卡

- BB 深度大數字 ＋ 健康徽章，沿用現有色階（<10 危險、10–20 短碼、20–30 可玩、30+ 健康）
- 下方一行「籌碼 34,000 · 盲注 200/400」，兩個數字各自可點：籌碼進面額編輯頁、盲注進盲注編輯頁
- 尚未設定盲注時 BB 顯示 `--`，該行改為引導設定盲注

### 籌碼變化卡

畫面主角，把「輸入 → 結果 → 歷史」收在同一張卡裡。

- 標題列：左「籌碼變化」，右「本場 +4,000」（正綠、負紅、零灰）
- 主列：贏／輸切換 → 數字輸入 → 記錄
- 快捷列：**固定 +1k／+5k／+10k** ＋「改總額」
  - 快捷鍵是**填進輸入框、可累加**（連按 +5k 兩次得 10,000），按「記錄」才寫入。誤觸不會直接改到籌碼。
  - 「改總額」開現有籌碼編輯頁，返回時照現行行為寫入一筆變化紀錄
- 底部：迷你長條圖 ＋「3 筆變化 · 起始 30,000 ›」，點進紀錄分頁
- 按下記錄後：籌碼與 BB 同步更新、輸入框清空、寫入一筆變化紀錄，並觸發 `.success` haptic
- 「輸」的金額大於目前籌碼時，於記錄當下夾到 0（輸入框允許先打大數字，不即時攔截）

### 升盲倒數卡

- 計時器關閉：顯示未啟用狀態 ＋ 啟用開關，不顯示升盲後 BB
- 啟用中：倒數、進度條、下一級盲注、**升盲後剩幾 BB**（套用同一套健康色）、暫停／繼續
- 點卡片空白處開啟計時器設定 sheet
- 升盲當下：狀態卡與本卡同步換值，並觸發 `.warning` haptic

## 資料與狀態

沿用不動：`chips`、`smallBlind`／`bigBlind`、`chipChangeRecords`、計時器整組鍵、`handActionLineRecords`、`chipBreakdown`、onboarding 旗標。Live Activity 的 payload 與差異推送節流邏輯不變。

新增一個鍵：`sessionStartChips`（本場起始籌碼）。

- 本場變化 = **目前籌碼 − 起始籌碼**，不是把每筆增減加總——因為「改總額」也必須算進去
- 本場以**重置**為界：按下重置即為一場結束，下次輸入的籌碼成為新的起始值
- 迷你長條圖直接取 `chipChangeRecords` 的籌碼序列（起始值 ＋ 最近 8 筆），不另存資料
- 舊資料沒有這個鍵時：取最早一筆變化紀錄的 `previousChips` 回推；連紀錄都沒有就等於目前籌碼（本場 ±0 起算）

升盲後 BB = 目前籌碼 ÷ 下一級大盲，取自現有的 `nextLevelBBCount`，必須走 `effectiveProgression()` 才不會在自訂結構上取到預設級距。

分頁選擇用 `@State`，不寫入 `AppStorage`。

## 檔案結構

`ContentView` 目前 604 行、`ResultView` 634 行，再加東西會失控。拆成：

- `RootTabView` — 四個分頁的殼，判斷「仍在輸入流程」或「已進入 Tab」
- `DashboardView` — 只負責組三張卡
- `StackStatusCard` / `ChipChangeCard` / `BlindTimerCard` — 三張卡各自獨立、可單獨預覽
- `SessionSummary` — 本場起始值、本場變化、長條圖資料的純邏輯型別
- `BlindOutlook` — 下一級盲注與升盲後 BB 的純邏輯型別，最後一級時回 nil

`ChipsInputView`、`BlindLevelView`、`TimerConfigSheet`、`HandActionLineSheet`、`ChipChangeHistorySheet` 內容不動，只換掛載位置。

## 邊界情況

| 情況 | 行為 |
| --- | --- |
| 尚未設定盲注（bb = 0） | BB 顯示 `--`，升盲卡改為引導設定盲注，籌碼變化卡照常可用 |
| 籌碼歸零 | BB = 0、健康色紅；「輸」的方向夾在 0，不出現負數 |
| 計時器關閉 | 升盲卡顯示未啟用狀態 ＋ 啟用開關，隱藏升盲後 BB |
| 已是盲注結構最後一級 | 顯示「已是最後一級」並隱藏升盲後 BB |
| 輸入框空白或 0 | 「記錄」按鈕 disabled |
| 金額超過 999,999,999 | 夾在上限（沿用現有規則） |
| 改總額後返回 | 本場變化自動重算 |
| 重置 | 清空籌碼／盲注／變化紀錄／計時器狀態／`sessionStartChips`，回到籌碼輸入流程 |
| 首次啟動 | onboarding → 籌碼 → 盲注 → Tab 介面 |
| 行動線／紀錄分頁無資料 | 沿用各自現有的空狀態畫面 |
| iPad | iPadOS 18 起分頁列呈現在頂部，不對抗系統行為；卡片沿用 640pt 置中上限 |
| 放大字級 | 卡片高度不寫死，數字以 `minimumScaleFactor` 保底 |

## 測試

計算邏輯先抽出 View 才可測。

**單元測試**

- 本場變化：起始 30,000 → 目前 34,000 得 `+4,000`；經過改總額後仍正確；舊資料以最早一筆 `previousChips` 回推；無紀錄時回 0
- 升盲後 BB：一般級距、自訂結構、已是最後一級時回 nil
- 快捷金額：連按累加；「輸」超過現有籌碼夾到 0；超過上限夾在 999,999,999

**UI 測試**

- 四個分頁皆可到達（新增 `tab.dashboard`／`tab.handline`／`tab.history`／`tab.settings` 識別碼）
- 主流程：輸入籌碼 → 盲注 → 儀表板 → 記錄贏 6,500 → BB 與本場變化同步更新
- 改寫現有兩個 UI 測試：它們斷言的底部按鈕在新版不存在，需改走分頁

**手動驗收清單**

- Live Activity 在升盲當下正確更新
- 暗光環境實機觀感
- 放大字級與 iPad 版面
